# Decisions

!!! abstract "TL;DR"
    - One line per technical decision the user stories and the plan rely on: what was chosen, and
      where the full record is when there is one.
    - BM25 is FTS5 on SQLite and ParadeDB on PostgreSQL behind one port; persistence is SQLAlchemy
      Core with one Alembic history; jobs are DBOS workflows.
    - The REST API under `/api/v1` is the only API the web UI and the CLI use. MCP is stateless
      Streamable HTTP at `/mcp`, with API tokens, and OAuth once ACL-01 is in.
    - AI retrieval is opt-in: pydantic-ai provider profiles, sqlite-vec or pgvector, budgets that
      degrade search and never fail it.

## All decisions

| Topic | Decision |
|---|---|
| BM25 engine (diagram: [Retrieval modes](../flows/retrieval-modes.md)) | SQLite **FTS5** locally, **ParadeDB** (`pg_search`) on PostgreSQL, behind one search port, with a shared ranking test suite and a custom tokenizer for identifiers (SRCH-01) |
| Version storage (diagram: [data model](../architecture/data-model.md)) | A version is a **manifest** (article path, tags, blob SHA) pointing at shared content;<br/>chunks are **deduplicated by (git blob SHA, chunking-config hash)**;<br/>the commit SHA lives on the version. Many tags and re-syncs stay cheap |
| Library settings | Paths, tag rules and chunking are **per library**;<br/>editing them re-processes every version of the library (cheap thanks to dedup), so versions stay comparable |
| Identifier tokenizer | Done **in Python before indexing**: expanded tokens (`camelCase` → `camel case`, `snake_case`, `--flag`, `pkg.mod.fn`) go into an extra indexed column, identical on FTS5 and pg_search |
| Chunker | Behind a port;<br/>the default adapter is **markdown-it-py** (issue #27: Chonkie's Markdown recipe needs the Hugging Face Hub and network, which breaks RUN-02, so it was dropped);<br/>heading-path and never-split guarantees are tested on the fixture repo whatever chunker is used |
| Git | The **system `git` binary** (in the Docker image; documented requirement for `uvx`), for `--filter=blob:none`, shallow fetch and sparse checkout |
| REST API | `/api/v1`, described by OpenAPI; the **only** API the web UI and the CLI use |
| Data location | Docker: `/data`; `uvx`: the platform user-data directory; stdio MCP uses the same default path |
| Agent stack (see [AI retrieval decisions](ai-retrieval.md)) | `pydantic-ai-slim` 2.60.0 + [`pydantic-ai-harness`](https://pydantic.dev/docs/ai/harness/) 0.60.0 and `pydantic-monty` (Code Mode without the harness's `[codemode]` extra, which pulls an unused search client), pinned to matching versions, in an optional `exactdocs[ai]` extra;<br/>never imported when no LLM or embedding model is configured |
| Web UI auth (diagram: [Authentication](../flows/authentication.md)) | Server **session cookie** (HttpOnly); API tokens are for MCP, REST and the CLI |
| MCP auth | API tokens verified by a FastMCP `TokenVerifier` (the token acts as its user);<br/>with ACL-01, FastMCP OAuth/OIDC (`OIDCProxy`) is combined with API tokens via `MultiAuth`, so web hosts (Claude, ChatGPT) can connect;<br/>OAuth discovery routes (`/.well-known/...`) are served at the root |
| MCP endpoint | **Stateless** Streamable HTTP (`stateless_http=True`) at `/mcp` (and `/mcp/` as an alias);<br/>every route of the MCP app (incl. OAuth `/.well-known/...`) is served as-is;<br/>errors are masked (`mask_error_details=True`) except `DomainError`s, which reach the agent as tool errors with their message;<br/>FastMCP's update check (`FASTMCP_CHECK_FOR_UPDATES=off`) and stdio banner are disabled |
| Host and origin checks | **One allowlist for the whole app** (REST, UI and MCP): localhost plus `EXACTDOCS_ALLOWED_HOSTS` (comma-separated, wildcards allowed), enforced by `TrustedHostMiddleware` and FastMCP's host/origin guard;<br/>state-changing browser requests with a foreign `Origin` get 403 (CSRF / DNS rebinding), unless the origin is listed in `EXACTDOCS_ALLOWED_ORIGINS` (comma-separated browser origins allowed to make state-changing requests);<br/>`EXACTDOCS_FORWARDED_ALLOW_IPS` tells uvicorn which proxies to trust |
| Telemetry | The plain **OpenTelemetry SDK** (Logfire was the first choice; dropped in #87, see *Telemetry* in docs/architecture/telemetry.md);<br/>OTLP over HTTP/protobuf to the operator's collector;<br/>FastAPI's built-in OpenTelemetry for requests (not `instrument_fastapi`, which records request arguments);<br/>pydantic-ai instrumentation with `include_content=False`;<br/>Prometheus via an additional OpenTelemetry metric reader;<br/>the SDK is only set up when `EXACTDOCS_TELEMETRY=otlp`, never with a console exporter (stdout belongs to stdio MCP) |
| HTTP client | `httpx2` (the client FastMCP 4 and pydantic-ai use), in every adapter |
| Web UI serving | FastAPI's `app.frontend(...)` for the built SPA (falls back to `index.html` only for HTML GET requests) |
| Users and tenancy | MVP: a **single admin** account. Next: an operator (role `admin`) creates, disables and resets further **local accounts** (role `user` or `admin`, no self-signup, ACL-06);<br/>library roles (viewer, contributor, admin, creator; users and groups) came with E12-05. **One tenant** per instance;<br/>library IDs are globally unique, like context7's |
| Background jobs (see [Architecture](../architecture/jobs/index.md) and the [import flow](../flows/import.md)) | MVP-1: an **in-process worker** with a job table in the database.<br/>MVP-2: jobs run as **DBOS** durable workflows (its own SQLite file in the data directory), so a killed import resumes at its last completed step (E3-11) |
| stdio MCP | A **standalone, in-process** server on the local database;<br/>opens it read-only (SQLite WAL), so it is safe next to a running HTTP server, except for the AI spend ledger, which it writes through a second, narrow connection (#274);<br/>works before any account exists |
| Refs containing `/` | Part of the path in MCP and context7 IDs (`/acme/payments/release/1.4`). REST routes are `/api/v1/libraries/{owner}/{repo}` and `.../versions/{ref:path}`, with the ref always last (servers decode `%2F` before routing, so encoded segments cannot work);<br/>routes that need a ref and an article path take both as query parameters (`?ref=` and `?path=`) |
| Persistence | **SQLAlchemy Core** (async, no ORM) with aiosqlite;<br/>**one Alembic history** owned by bootstrap, with `render_as_batch=True` (SQLite) and FTS5 tables created via `op.execute`;<br/>tables prefixed per domain (`catalog_`, `retrieval_`, ...);<br/>**no cross-domain foreign keys** (other domains' IDs are held by value) |
| Vector storage ([details](ai-retrieval/local-models.md#vector-store)) | One `VectorIndex` port;<br/>**sqlite-vec** on SQLite (float32 BLOBs, `vec_distance_cosine`), **pgvector** on PostgreSQL and Supabase;<br/>one table per embedding space (model, dimensions and input format recorded), exact search scoped to the active manifest;<br/>a model change builds a new space while BM25 answers. Replaces the earlier numpy brute force |
| AI providers ([details](ai-retrieval/providers.md#provider-abstraction)) | Named provider profiles mapped to pydantic-ai providers, always built with explicit URLs and keys (never `OPENAI_API_KEY` and the like):<br/>custom OpenAI-compatible (base URL, optional key), OpenAI, OpenRouter, Anthropic (also Claude on Vertex AI and Azure AI Foundry), Azure OpenAI (key or Entra ID), Google Vertex AI and Gemini, Ollama, vLLM, LiteLLM and pydantic-ai's other OpenAI-SDK platforms;<br/>roles `embedding`, `reranker`, `llm`, `judge`;<br/>configured in env or a TOML file, or in the UI with keys sealed by the secret box (moving to bootstrap, #248);<br/>per-library overrides except the embedding model. Embeddings and rerankers sit behind our own ports (pydantic-ai `Embedder`, Cohere-compatible/TEI HTTP, fastembed) |
| Local models and images ([details](ai-retrieval/local-models.md#local-and-offline-models)) | Optional `exactdocs[local]` extra: **fastembed** on ONNX Runtime (CPU), default `BAAI/bge-small-en-v1.5` and `Xenova/ms-marco-MiniLM-L-6-v2`, loaded from `EXACTDOCS_MODELS_DIR` (default `<data dir>/models`), never downloaded at run time.<br/>Images: base (410 MB, BM25), `-ai` (560 MB), `-local` (950 MB, models included) |
| AI cost ([details](ai-retrieval.md#cost-and-budgets)) | Token and USD budgets per instance, library and user (daily, monthly) in one database table: harness `SpendLimits` over a `BatchSpendStore` for LLM agents, retrieval's own check before each embedding batch or rerank call;<br/>LLM searches per minute limited inside retrieval;<br/>a limit degrades to a cheaper mode with a `fallback_reason`, never an error |
| PostgreSQL and Supabase ([details](ai-retrieval.md#databases)) | psycopg 3 (already in the image through DBOS);<br/>DBOS's tables in the same database (`system_database_url` set to it, plus `dbos_system_schema`), never a separate system database;<br/>ParadeDB `pg_search` for BM25;<br/>on databases without it (Supabase), PostgreSQL full-text search behind the same search port;<br/>Supabase only as a database, session connections, pgvector in `extensions` |
| External sign-in (Teams; [details](ai-retrieval.md#sign-in-for-the-teams-milestone)) | Named providers next to local accounts: `oidc` (ADFS included), `oauth2`,<br/>`github` (github.com, a GHE Server host or `*.ghe.com`, with an optional `api_url`; organization and team membership checked via the GitHub API at sign-in and every hour, 403s for unapproved apps or SAML SSO reported as such);<br/>OIDC/OAuth2 revalidation needs a refresh token, without one a session ends after the grace period;<br/>Authlib for the web, FastMCP `OIDCProxy` / `OAuthProxy` + `MultiAuth` for MCP |
| Benchmark history ([details](benchmark-history.md)) | Every recorded run in a committed `evals/results/history.json`, written by `just bench-pages` and checked by pytest; rows deduplicated by content (a row keeps the date and commit of its first run);<br/>one *Every run* page per benchmark: a Markdown table that plain JavaScript and inline SVG turn into a sortable, filterable table with a chart, no library |
| Page size ([details](page-size.md)) | A page in `docs/` over **16 KiB** (`wc -c`, about two 8,000-character chunks) is split into an index (TL;DR and a *Pages* table) and sub-pages by topic;<br/>old anchors stay as a *Moved sections* list on the index, no redirect plugin |
| Eval environments and Dependabot ([details](eval-environments-dependabot.md)) | The coding tasks' environments (`evals/coding/environments/*`) pin one old library version each on purpose; Dependabot opens no version or security PRs for them (`open-pull-requests-limit: 0`, every dependency ignored, no `target-branch`);<br/>their alerts are dismissed as "vulnerable code is not actually used", since they run only in the evals' offline sandbox |
| Adding libraries over MCP ([details](mcp-write-tools.md)) | Two tools, `add_docs` and `import_status`, on the existing ingestion driving ports;<br/>only for callers who may create libraries (instance admins and `[library_creation].groups`, #110), hidden from everyone else with FastMCP's component-level `auth=` (fallback: listed, and a call is refused);<br/>no removal over MCP; `https://` sources only, from `EXACTDOCS_MCP_IMPORT_HOSTS`, never a private or metadata address. Design accepted, built in #613 |
| CI runners ([details](ci-runners.md)) | Every self-hosted job on our **GCP runners** `[self-hosted, linux, ARM64, exactdocs, gcp]` (five 2-vCPU ARM64 VMs, persistent);<br/>`RUNNER_MODE=self-hosted`, `hybrid` moves CI back to GitHub-hosted runners;<br/>a fork's pull request always on GitHub-hosted `ubuntu-24.04`, after approval |
| Role rules ([details](role-rules.md)) | A rule maps a provider's group, role value, GitHub organization or team to `instance_admin`, `create_libraries` or a library role;<br/>library roles computed at every request (never written as grants), instance admin stored and recomputed at sign-in and each membership check;<br/>rules for every library leave out private libraries; a rule matches only its provider's accounts; role values in their own table |
